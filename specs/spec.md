## Общее описание

Компилируемый язык программирования с сильной статической типизацией. Преобразования типов и изменяемость переменных указываются явно. Сборщика мусора нет.

Структура кода задается отступами (как в Python), фигурные скобки не используются. Отступы только пробелами, табуляция запрещена. Комментарии начинаются с # и идут до конца строки. Идентификаторы только латиницей.

Кроме однострочных, поддерживаются блочные комментарии `/* ... */` (доп. A.1.15) — могут занимать несколько строк и быть вложенными друг в друга (`/* a /* b */ c */` — целиком комментарий). Незакрытый блочный комментарий — ошибка лексера: `unterminated block comment` с позицией открывающего `/*`.

Целые числа: 42. Вещественные: 3.14, цифры обязательны с обеих сторон точки. Строки в двойных кавычках, поддерживают \n, \t, \\ и \". Перенос строки внутри строкового литерала запрещен.


## Ключевые слова

Их нельзя использовать как имена переменных или функций:

```
def  let  var  if  else  while  break  continue  return
struct  type  namespace  as  and  or  not  true  false  void

print  input  exit  panic  len  sizeof  typeof

int8  int16  int32  int64  uint8  uint16  uint32  uint64
float32  float64  bool  string  void  array
```

## Грамматика

```
program     ::= { top_decl } EOF
top_decl    ::= func_decl | struct_decl | type_alias | namespace_decl

func_decl      ::= def IDENT ( [ param_list ] ) -> type : block
param_list     ::= param { , param }
param          ::= IDENT : type

struct_decl    ::= struct IDENT : NEWLINE INDENT { field_decl } DEDENT
field_decl     ::= IDENT : type NEWLINE

type_alias     ::= type IDENT = type NEWLINE

namespace_decl ::= namespace IDENT : NEWLINE INDENT { top_decl } DEDENT

block         ::= NEWLINE INDENT { stmt } DEDENT
stmt          ::= var_decl | assign_stmt | if_stmt | while_stmt
                | return_stmt | break_stmt | continue_stmt | expr_stmt

var_decl      ::= ( let | var ) IDENT [ : type ] = expr NEWLINE
assign_stmt   ::= lvalue = expr NEWLINE
lvalue        ::= IDENT | lvalue [ expr ] | lvalue . IDENT
if_stmt       ::= if expr : block [ else : block ]
while_stmt    ::= while expr : block
return_stmt   ::= return [ expr ] NEWLINE
break_stmt    ::= break NEWLINE
continue_stmt ::= continue NEWLINE
expr_stmt     ::= expr NEWLINE

expr         ::= or_expr
or_expr      ::= and_expr { or and_expr }
and_expr     ::= not_expr { and not_expr }
not_expr     ::= not not_expr | cmp_expr
cmp_expr     ::= add_expr [ ( == | != | < | > | <= | >= ) add_expr ]
add_expr     ::= mul_expr { ( + | - ) mul_expr }
mul_expr     ::= unary_expr { ( * | / | % ) unary_expr }
unary_expr   ::= - unary_expr | cast_expr
cast_expr    ::= postfix_expr [ as type ]
postfix_expr ::= primary_expr { [expr] | .IDENT | ::IDENT | ([arg_list]) }
primary_expr ::= INT_LIT | FLOAT_LIT | BOOL_LIT | STRING_LIT | IDENT
               | ( expr ) | array_lit | struct_lit
               | sizeof ( type ) | typeof ( expr )
array_lit    ::= [ [ expr { , expr } ] ]
struct_lit   ::= IDENT { [ field_init { , field_init } ] }
field_init   ::= IDENT : expr
arg_list     ::= expr { , expr }

type ::= int8 | int16 | int32 | int64
       | uint8 | uint16 | uint32 | uint64
       | float32 | float64 | bool | string | void
       | array [ type , INT_LIT ]
       | IDENT
```

### Приоритет операторов (от слабее к сильнее)

| # | Операторы | Ассоциативность |
|---|-----------|-----------------|
| 1 | or | левая |
| 2 | and | левая |
| 3 | not | правая |
| 4 | == != < > <= >= | нет (нельзя писать a < b < c) |
| 5 | + - | левая |
| 6 | * / % | левая |
| 7 | унарный - | правая |
| 8 | as | левая |
| 9 | [] . :: () | левая |


## Переменные

Есть два вида: let - нельзя менять после объявления, var - можно. Инициализация обязательна, объявить переменную без значения не получится. Параметры функций тоже нельзя менять, они как let.

Переменная видна от места объявления до конца своего блока. Во вложенном блоке можно объявить переменную с тем же именем - она перекроет внешнюю. Объявить одно имя дважды в одном блоке нельзя.


## Функции

Функции объявляются только на верхнем уровне или внутри namespace. Функции внутри функций нет.

Если функция что-то возвращает (не void), она обязана дойти до return с нужным значением. Функции видят друг друга независимо от порядка объявления, так что взаимная рекурсия работает.

Точка входа в программу - функция main без параметров, возвращает int32. Это число уходит в операционную систему как код завершения.

Аргументы передаются по значению - функция получает копию и что угодно с ней делает, оригинал не трогается.


## Структуры, массивы и строки

Структуры - набор именованных полей. При создании надо заполнить все поля, порядок не важен. Доступ через точку. Если переменная объявлена через let, поля тоже менять нельзя.

Массивы имеют фиксированный размер, который задается в типе: array[int32, 5]. Размер - часть типа, так что массивы разного размера - разные типы. Индексация с нуля, выход за границы - ошибка в рантайме.

Строки неизменяемые. Можно склеивать через +, сравнивать через == и !=, узнавать длину в байтах через len.

Присваивание всегда делает полную копию - для структур и массивов тоже. После b = a они живут независимо.


## Остальное

Namespace группирует объявления под общим именем, доступ снаружи через ::. Внутри namespace всё видно напрямую. Можно вкладывать namespace в namespace.

type A = B - просто псевдоним, новый тип не создается, A и B полностью взаимозаменяемы.


## Встроенные функции

| | |
|-|--|
| print(x) | выводит значение с переносом строки, работает с любым встроенным типом |
| input() | читает строку из stdin |
| exit(code) | завершает программу с кодом int32 |
| panic(msg) | падение с сообщением в stderr, код выхода 1 |
| len(x) | длина массива или строки в байтах, возвращает int32 |


## Ошибки в рантайме

Программа падает с сообщением "runtime error: ... at line N" в stderr. Это происходит при делении на ноль, остатке от деления на ноль и выходе за границы массива. Вызов panic тоже роняет программу - намеренно.


## Запуск компилятора

`compiler [файл.csm] [флаги]`. Если файл не указан, программа читается из stdin.

| Флаг | Действие |
|------|----------|
| `-o <файл>` | путь для итогового файла ассемблера (по умолчанию `<файл>.s`, либо `out.s` для stdin) |
| `--tokens` | вывести поток токенов и завершиться |
| `--ast` | вывести AST в текстовом виде и завершиться |
| `--tree` | вывести AST как дерево и завершиться |
| `--optimize` | доп. B.2.4 — применить оптимизации AST перед выводом/кодогенерацией (см. ниже) |
| `--emit-asm` | доп. B.1.8 — остановиться после генерации `.s`, не печатать подсказку по сборке в stderr (для скриптов) |
| `--time-phases` | доп. B.1.8 — вывести в stderr время каждой фазы (lexer/parser/semantic/optimize/codegen) в мс |

При ошибке лексера/парсера/семантики компилятор печатает `<файл>:<строка>:<столбец>: error: <сообщение>` в stderr и завершается с кодом 1.


## Оптимизации AST (`--optimize`, доп. B.2.4)

Флаг `--optimize` запускает проход по AST после семантической проверки и перед выводом `--ast`/`--tree` и кодогенерацией. Преобразования сохраняют семантику программы:

- **свёртка констант** — арифметика, сравнения и логические операции над литералами (`2 + 3 * 4` → `14`, `1 == 2` → `false`), конкатенация и сравнение строковых литералов, унарные `-`/`not` от литералов;
- **удаление мёртвых веток** — `if` с константным условием заменяется содержимым нужной ветки (`else` удаляется, если условие истинно, и наоборот); `while false: ...` удаляется целиком;
- **алгебраические упрощения** — `x + 0`, `0 + x`, `x - 0`, `x * 1`, `1 * x`, `x / 1` → `x`; `x * 0` / `0 * x` → `0`, но только если `x` не содержит вызовов функций (побочных эффектов).

Деление и остаток от деления на константный `0` не сворачиваются — программа сохраняет прежнее поведение (runtime error "division by zero"). Результат можно посмотреть через `--optimize --tree` (см. `examples/ast_optimize.csm`).


## sizeof и typeof (доп. A.1.13)

Две встроенные метафункции, вычисляемые целиком на этапе семантической проверки — в готовый код попадает только результат (целочисленный или строковый литерал).

`sizeof(type)` — размер типа в байтах как `int32`. Поддерживаются числовые типы (`int8`..`int64`, `uint8`..`uint64`, `float32`, `float64`), `bool`, массивы фиксированного размера из таких типов (рекурсивно, размер = размер элемента × длина) и `type`-псевдонимы, ведущие к перечисленным типам. Для `string`, `void`, имён структур и любых других неподходящих типов — ошибка семантики: `sizeof: unsupported type '<тип>'`.

`typeof(expr)` — статический тип выражения как строковый литерал (`"int32"`, `"float64"`, `"string"`, `"bool"`, `"array[int32, 5]"`, имя структуры и т.п. — в том же формате, что и сообщения об ошибках типов). Выражение проверяется типом, но **не вычисляется** во время выполнения (как `decltype`) — побочные эффекты внутри `typeof(...)` не происходят.

Обе метафункции — часть `primary_expr`, поэтому их результат можно использовать в любом выражении: `let n: int32 = sizeof(int64) * 2`, `print(typeof(x))`.
